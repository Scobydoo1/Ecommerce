# Phase 1 MVP (Storefront + Smart Search) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship a working storefront where a customer can find a product despite typos or missing Vietnamese diacritics, view it, add it to a cart, pay through Stripe test mode, and receive an order confirmation.

**Architecture:** pnpm + Turborepo monorepo. Two NestJS services (`catalog-service` :3001, `order-service` :3002) share one Postgres database but own separate Postgres schemas (`catalog`, `orders`), each with its own Prisma migration history. A Next.js 14 App Router storefront (:3000) renders SSR pages and owns customer auth via Auth.js (schema `auth`). Search is a strategy-based pipeline fused with Reciprocal Rank Fusion; Phase 1 registers only the pg_trgm strategy while the pgvector column and HNSW index are created up front for Phase 2.

**Tech Stack:** TypeScript, NestJS 10, Prisma 6, Next.js 14, TailwindCSS, Postgres 16 (`pgvector/pgvector:pg16` with `pg_trgm`/`unaccent`/`vector`), Redis 7, Stripe, Jest, Testcontainers, Playwright.

## Global Constraints

- Follow `CLAUDE.md` exactly; it is the source of truth. This plan implements Phase 1 only — no Phase 2/3/4 work.
- Node ≥ 20, pnpm 11.21.0 (declared in root `packageManager`).
- Directories `kebab-case`; React components `PascalCase.tsx`; utils `camelCase.ts`.
- All money is **integer cents**. Never a float, at any layer.
- No hardcoded secrets. Everything through `.env`. `.env` is gitignored; `.env.example` is committed.
- Never log PII (email, phone) or any payment payload.
- Every NestJS endpoint validates input with `class-validator` and a global `ValidationPipe({ whitelist: true, transform: true })`.
- TDD: for every piece of business logic the failing test is written and *run* before the implementation exists.
- Every task ends with `pnpm lint` and `pnpm test` green, then a Conventional Commit.
- Do not create empty directories "for later".
- Packages beyond `CLAUDE.md` §3 are limited to these three, each already justified in the spec: `@testcontainers/postgresql`, `@nestjs/throttler`, `next-auth@5`.

Note: `embedding vector(1536)` and the trigram/HNSW indexes are not expressible in Prisma schema syntax. They are added in Step 2 as raw SQL appended to the generated migration.

- [ ] **Step 2: Generate the migration, then append the raw SQL Prisma cannot express**

Run: `pnpm --filter catalog-service exec prisma migrate dev --name init --create-only`

Then append to the generated `migration.sql`:

```sql
ALTER TABLE "catalog"."Product" ADD COLUMN "embedding" vector(1536);

CREATE INDEX "Product_name_trgm_idx"
  ON "catalog"."Product" USING GIN (lower(unaccent("name")) gin_trgm_ops);
CREATE INDEX "Product_description_trgm_idx"
  ON "catalog"."Product" USING GIN (lower(unaccent(coalesce("description", ''))) gin_trgm_ops);
CREATE INDEX "Product_embedding_hnsw_idx"
  ON "catalog"."Product" USING hnsw ("embedding" vector_cosine_ops);
```

`unaccent` is not `IMMUTABLE` by default, which blocks its use in an index expression. Before the index statements, add:

```sql
ALTER FUNCTION unaccent(text) IMMUTABLE;
```

## Task 7: Reciprocal Rank Fusion (M4, TDD)

**Files:**
- Create: `services/catalog-service/src/search/types.ts`, `services/catalog-service/src/search/fuseResults.ts`
- Test: `services/catalog-service/test/unit/fuseResults.spec.ts`

**Interfaces:**
- Produces:

```ts
export interface SearchHit { productId: string; score: number }
export interface RankedList { strategy: string; hits: SearchHit[] }
export interface SearchOptions { limit: number; offset: number; categoryId?: string }
export interface SearchStrategy {
  readonly name: string;
  search(normalizedQuery: string, options: SearchOptions): Promise<SearchHit[]>;
}
export function fuseResults(lists: RankedList[], k?: number): SearchHit[];
```

`fuseResults` treats each list as already ranked (index 0 = rank 1), scores `1 / (k + rank)` with `k = 60` by default, sums across lists, sorts by score descending, and breaks ties by `productId` ascending so output is deterministic.

- [ ] **Step 1: Write the failing test**

```ts
import { fuseResults } from '../../src/search/fuseResults';

const list = (strategy: string, ids: string[]) => ({
  strategy,
  hits: ids.map((productId) => ({ productId, score: 0 })),
});

describe('fuseResults', () => {
  it('returns an empty array for no lists', () => {
    expect(fuseResults([])).toEqual([]);
  });

  it('preserves order for a single list', () => {
    const out = fuseResults([list('trigram', ['a', 'b', 'c'])]);
    expect(out.map((h) => h.productId)).toEqual(['a', 'b', 'c']);
  });

  it('scores rank 1 as 1/(k+1)', () => {
    const out = fuseResults([list('trigram', ['a'])], 60);
    expect(out[0].score).toBeCloseTo(1 / 61, 10);
  });

  it('ranks a document appearing in both lists above one appearing in only the top of a single list', () => {
    const out = fuseResults([
      list('trigram', ['x', 'shared']),
      list('vector', ['y', 'shared']),
    ]);
    expect(out[0].productId).toBe('shared');
  });

  it('breaks score ties deterministically by productId', () => {
    const out = fuseResults([list('trigram', ['b']), list('vector', ['a'])]);
    expect(out.map((h) => h.productId)).toEqual(['a', 'b']);
  });

  it('ignores empty lists without affecting scores', () => {
    const withEmpty = fuseResults([list('trigram', ['a', 'b']), list('vector', [])]);
    const without = fuseResults([list('trigram', ['a', 'b'])]);
    expect(withEmpty).toEqual(without);
  });
});
```
